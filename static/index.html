Processed invoices

This is a record of every invoice the application has processed, from Single Invoice and Batch Invoices runs alike. Point at Validation, Decision, or Payment for a definition. Point at a red or amber value for the reason behind it. Click a row to open a full breakdown in a new window. Click Edit on a row to propose a change to that invoice.

Edit requests

Every manual edit you have submitted, whether it is still pending, approved, or rejected. Open Edit Approvals to act on a pending request.

Edit approvals

Escalated invoices and edit requests that are waiting for a decision before the application acts on them.

In this demo, you resolve escalated invoices and approve your own edit requests yourself. In a real deployment, a separate approver would handle these.

Inventory database

The validation agent checks every invoice line item against this data. Edit stock, unit price, or category directly below, then click Save Changes. Click Reset to Original at any time to restore the starting values.

Action log

Every call the application makes to the LLM provider: reading a free-text or PDF invoice, drafting an approval decision, and critiquing that draft. Each entry shows the invoice or file it was for, the prompt sent, and either the model's result or the error if the call failed.

The application saves your key in a local file on this machine. Git does not track this file. The application never sends the full key back to the browser. It only shows a masked version of the key.

This provider has no API key. JSON, CSV, and XML invoices still parse and validate on the Single Invoice tab. Free-text and PDF invoices need a key. Every approval decision needs a key. Paste a key above and click Save.

Full reset

This deletes every processed invoice, edit request, notification, and action log entry. It also resets the inventory and clears the payment ledger, the same as Reset Inventory and Ledger. This cannot be undone.

Type RESET below to confirm. The application deletes this data right away.
